07One cycle, step by step

One cycle: three lanes, nine reviews, one gate

agentshell stepcontrol or end nodeOpus 5.5 xhighStop early: touch .factory/STOP, the line finishes its cycle and writes the final report.
  1. keeper-dispatch (Opus 5.5 low) fills batch.json: up to 3 slots, ports 3101 to 3103.
  2. 3 workers (Opus 5.5 medium) build in their own git worktree and open a PR labelled factory.
  3. 3 critics per lane (Opus 5.5 medium): reviewer, devil's advocate, verifier. Each ends in VERDICT: PASS or FAIL.
  4. ci-snapshot.sh collects CI checks, head SHA, merge state and the three verdicts.
  5. judge (Opus 5.5 medium). PASS goes to the gatekeeper.
  6. fix-gate: FAIL or PARTIAL sends the fixers back to review, up to 3 rounds.
  7. gatekeeper (Opus 5.5 xhigh) reads every diff, merges one at a time, may call apply-migration.sh.
  8. notify (Telegram, now off).
  9. keeper-stamp (Opus 5.5 low) updates the backlog and the ledger.
  10. clock.sh 60: the next cycle, or the final report.
08The strict rule
PASS with a minor issue is a FAIL.

From the gatekeeper's prompt. The reviewers held the same bar.

The judge passes a PR only when
  1. all three reports exist,
  2. all three end in PASS,
  3. every report's SHA: line equals the PR head,
  4. every CI check passes.

A review of an older commit does not count.

09Production safety

Nothing touched production without a script that could say no

1worktree HEAD must equal origin/factory/<slug>
2branch must contain origin/main
3only new files in web/drizzle/*.sql, none modified or deleted
4each new file numbered above main's latest
5refuses drop, delete, update, truncate, rename, replace and a foreign key pragma

#it answers with one line

>MIGRATION_APPLIED <files> (restore point <bookmark>)

18What broke, and what was done

Nine things broke, and what was done about each

BrokeWhat was done
01Agents defaulted to read-only: the first run reported ok and collected nothing.A probe confirmed it. Every station that writes got the code role.
02The judge has no shell, so it could not check CI or the PR head.ci-snapshot.sh hands it checks, head SHA, merge state and verdicts.
03The default 60-step limit ended shift 1 after 1 h 59 min.maxSteps went to 1,000. The next run resumed at the judge.
04Stopping a run left its fixer tabs working in the same worktrees.The orchestrator closed them by hand, and 101 finished tabs on Oct 30. Still open: see slide 19.
05The deadline was only checked between cycles: shift 1 merged after it.clock.sh 60 calls time 60 minutes early.
06The migration script flagged ON DELETE cascade and once printed an empty restore bookmark.Foreign key actions stripped before the check. Bookmark capture fixed.
07A stale LLM Gateway key (HTTP 401) blocked live verification of #17 and #18.New key, set as the Worker secret, runner restarted.
08GitHub cancelled a CI run on #14: Actions cache over its egress limit.No fix: nothing was wrong with the code. The judge counts a cancelled check as not passing, so it waited a cycle and went green on the rerun.
09Two stations could send to Telegram, so some merges arrived twice.Turned off. notify-telegram.sh now only logs.
19What I would change

Five changes for the next line

1

Stop committing generated files

Most holds after a merge were conflicts in sitemap.xml, llms.txt and a marketing audit table. Generate them at deploy time.

2

Give reviewers a CPU budget

Three gatekeeper catches were regexes or scans that got slow on hostile input. Time every new regex on 100,000 characters.

3

Check keys at boot

The stale key surfaced in a verifier, hours in. boot.sh should call every external service once and refuse to start if one fails.

4

Stop child tabs with the run

And check the deadline inside long stations, not only between cycles. Both were orchestrator lessons.

5

One notifier

Two stations that can send the same message will.
